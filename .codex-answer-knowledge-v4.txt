## 1. Mixer 与读出位置

去掉 mixer 后，每个统计量仍保持独立编译：

\[
u_i=\mathrm{RMSNorm}(phrase_i+value_i)
\]

不会发生统计量之间的预先混合。进入冻结 LLM 后，LLM 的 causal attention 仍会进行跨 token 信息聚合，这是必要的，不等同于破坏统计量身份。

直接读取第 32 个统计量的 hidden technically 可行，因为它能看到前面的 31 个统计量。但它同时具有：

- 固定的第 32 个位置；
- `aperiodic spectral slope` 的固定短语身份；
- 自身数值的最强影响；
- 可能被模型当作捷径特征。

这类似于“把最后一个内容 token 当 EOS 用”，能工作，但不如真正的终止读出 token 稳定。

推荐布局：

```text
[start][task prompt][end][knowledge_1 ... knowledge_32][READOUT]
```

`READOUT` 是一个独立的、可学习的 4096 维向量：

```text
readout_embedding: R^4096
```

它不经过 phrase/value 编译器，不对应任何统计量。最终只读取其 hidden state：

```text
h_readout = hidden[:, readout_position, :]
```

直接读取第 32 个 token 可以保留为 ablation，但不建议作为主设计。

## 2. 读出维度

推荐使用完整的 4096 维：

```text
RMSNorm(4096) -> Linear(4096, out_dim)
```

不建议直接取 hidden 的前 128 维。LLM hidden 的前若干维没有特殊语义，截断会丢弃信息，而且 `d_ff=128` 只是仓库原有 head 约定，不是理论上合理的读出子空间。

如果确实需要正则化，应使用可学习 bottleneck：

```text
4096 -> 128 -> out_dim
```

而不是：

```text
hidden[:, :128]
```

由于输出类别通常很少，`Linear(4096, 1/2)` 的参数量并不大，完整维度更合理。

## 3. 共享 `4096 -> 128` 投影

去掉 mixer 后，原共享投影不再承担 token mixer 的接口作用。它仍可作为瓶颈或正则化，但不是必须的。

推荐删除外部共享投影，并把它折叠进 `ReprogrammingLayer`：

```text
u_i:       4096
query:     Linear(4096, 128)
key:       prototype 4096 -> 128
value:     prototype 4096 -> 4096
output:    4096
```

其中 128 是 attention 的总 query/key 维度；如果使用多头，则满足：

```text
num_heads * head_dim = 128
```

最终形状为：

```text
u:       (B, 32, 4096)
q:       (B, 32, 128)
soft:    (B, 32, 4096)
```

注意 attention 的 softmax 应该只在 prototype bank 维度上进行，不能在 32 个统计量之间做 token-token attention，否则又会引入统计量混合。

这样做的优点是：

- 没有无意义的 `4096 -> 128 -> query_projection` 双重瓶颈；
- 每个统计量仍独立通过同一个 query projection；
- attention 内部仍保留 128 维，计算量不变；
- prototype 的 4096 维表达能力仍保留在 value/output 路径。

## 4. 序列布局与位置编码

最终序列：

```text
[start_tag][task_prompt][end_tag]
[knowledge_1] ... [knowledge_32]
[READOUT]
```

`start_tag/end_tag` 仍然只包围文本任务提示，不要把 knowledge 或 readout 放进文本标签区域。

### LLaMA

使用全局 RoPE：

- 原有 token 的位置不变；
- `READOUT` 使用 knowledge 第 32 个 token 的下一个位置；
- 不要在 knowledge 区域重新从位置 0 开始；
- 序列最大长度增加 1；
- 不要在 readout 后再自动追加 EOS，否则最后位置可能不再是 readout。

### ChatGLM 2D position

保持当前的 prompt block 和 knowledge block 结构：

- `knowledge_1 ... knowledge_32` 与 `READOUT` 属于同一个 knowledge block；
- `READOUT` 使用该 block 的下一个 intra-block position；
- 不要把 readout 建成新的 prompt block；
- 更新 position ids 和 attention mask，使 readout 可以看到全部文本和 32 个 knowledge token。

如果批处理中存在 padding，不要无条件读取 `hidden[:, -1, :]`，应根据 readout 的实际位置索引读取。

## 5. 最终模块与实现顺序

1. 保持原始特征计算不变：

   ```text
   EEG -> z-score -> static FC -> 32 display stats
   ```

2. 每个统计量独立生成 4096 维向量：

   ```text
   phrase_i: frozen 4096
   value_i:  scalar -> 4096
   u_i = RMSNorm(phrase_i + value_i)
   ```

3. 删除 32-token mixer。

4. 修改 ReprogrammingLayer：

   ```text
   query input: 4096
   attention dimension: 128
   output dimension: 4096
   ```

5. 生成 32 个 soft knowledge tokens，并追加一个独立的 4096 维可学习 `READOUT` token。

6. 拼接并送入冻结 LLM：

   ```text
   [text embeddings][32 soft knowledge embeddings][readout embedding]
   ```

7. 读取 readout hidden：

   ```text
   h = LLM_hidden(readout_position)
   h = RMSNorm(h)
   prediction = Linear(4096, out_dim)(h)
   ```

8. 保持原有 loss：

   - 分类：CE；
   - 回归：Huber；
   - loss 和回归指标计算使用 fp32。

## 训练稳定性

- FC、频谱、形态统计、phrase/value、RMSNorm、Q/K attention 和 softmax 保持 fp32。
- soft knowledge tokens 与 readout 在进入 LLM 前统一转换为 bf16。
- LLM 权重冻结，并建议保持 `eval()`，避免冻结 backbone 的 dropout 引入额外噪声。
- `READOUT` 初始化为零均值、RMS 与 LLM 词嵌入相近的随机向量，不建议直接使用带明显词义的词向量。
- Query/key/output projection 使用 Xavier 类初始化；确保 reprogram 输出的 RMS 与 LLM 输入 embedding 尺度相近。
- 每个 `value_i` 的初始化应使其在典型统计量范围内的 RMS 明显小于或接近 phrase RMS，避免数值分支一开始完全淹没短语身份。
- 使用短 warmup、梯度裁剪，并记录 knowledge token 和 readout 的 RMS、attention entropy。
- 删除 mixer 后，旧 checkpoint 不能完全兼容。旧的 mixer 参数应忽略，新的 readout/head/query projection 重新初始化，并在 checkpoint 配置中记录架构版本。

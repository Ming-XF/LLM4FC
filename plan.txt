当前的原型映射在 TimeLLM.py 两处：

  1. 定义（第 206 行）：self.mapping_layer = nn.Linear(vocab_size, num_prototypes)
  2. 使用（第 342–346 行）：
  we = self.word_embeddings.permute(1, 0)          # (d_llm, vocab_size)
  source_embeddings = self.mapping_layer(we).permute(1, 0)  # (num_prototypes, d_llm)

  这里 mapping_layer 是确定性线性映射，且与输入无关：它对冻结的 word embedding
  矩阵做一次全局变换，产出一组 num_prototypes 个所有样本共享的 text prototype，作为 reprogramming_layer
  的 key/value。query 才是输入相关的 GCN node_embeddings。

  所以"把原型映射改成 VAE 重参数化"要改的就是这条 vocab_size → num_prototypes 的确定性映射。

  设计建议：两个落点，先选语义

  关键决策是 采样得到的 latent 是"全局 codebook"还是"逐样本条件"，这决定了原型还换不换语义。

  方案 A（推荐）：对全局 prototype codebook 做 VAE

  保持"原型是所有样本共享的 codebook"这一语义不变，只把确定性映射换成概率映射：

  - 编码器：Linear(vocab_size, 2·latent_dim)，作用于 we，得到每个原型对应的 mu、logvar（形状
  num_prototypes × latent_dim）
  - 重参数化：z = mu + sigma·eps，eps ~ N(0, I)
  - 解码器：Linear(latent_dim, d_llm)，把 z 映射回原型 token 空间 → source_embeddings (num_prototypes, 
  d_llm)
  - KL loss：KL(N(mu, sigma) || N(0, I))，直接加进 forward 返回的 loss 里

  这是最忠实的"采样后映射为原型"，改动最小，且天然契合你当前 loss 单标量的约定（trainer 只读
  outputs.loss，辅助 loss 必须在 forward 里加好）。

  方案 B：条件 VAE（原型变成逐样本的）

  编码器输入改为 GCN 的 node_embeddings（pool 后），采样出 z (B, latent_dim)，再 decode
  成每样本一套原型。好处是原型变成"内容寻址"，坏处是：

  - 语义大变：原来"LLM 共享词典"的性质没了，reprogramming 变成样本级 memory
  - 计算量：每样本 decode num_prototypes × d_llm（500×4096）向量
  - 与 freeze_for_finetune、few-shot transfer 的"冻结 reprogram 层"逻辑冲突更大

  我建议先做 A，若 A 的随机性带来的收益明显再考虑 B。

  几个必须处理的细节

  1. KL 权重 / 退火（beta-VAE）：直接 loss = task_loss + beta·kl 很容易 KL
  collapse（后验塌缩到先验，重参数化退化成无信息）。建议 beta 从小（如 1e-3）起步，或随 epoch 从 0
  线性退火到 1，加一个 --vae_beta / --vae_anneal 参数。
  2. 训练/推理分支：训练时采样 z，推理时必须用 mu（确定性），否则测试集结果带采样噪声、不可复现。用
  self.training 判断即可。
  3. dtype：LLM 是 bfloat16，但你现有的 node_projection、mapping_layer 都在 float32 跑、最后才 cast。VAE
  的 encoder/decoder/重参数化也应走 float32，最后 source_embeddings.to(bfloat16) 再喂给
  reprogramming（和现有 348–355 行的 dtype 处理对齐）。
  4. freeze_for_finetune：需要把新增的 VAE 模块（mu/logvar 投影、decoder）一并
  requires_grad_(False)，否则 few-shot transfer 时这些层还在更新。
  5. 参数规模：当前 mapping_layer 是 num_prototypes × vocab_size（500 × 词表大小，很大），换成 latent_dim
  × d_llm 的 decoder 反而更省。latent_dim 建议 16~64。

  一点关于"为什么做这个"的提醒

  VAE
  重参数化本质是给原型流形加一个平滑/正则先验，不是直接的域不变机制——它更多是"抑制源域原型过拟合"，对你
  plan.txt 里的跨域泛化是辅助性的。如果目标是跨域，建议把它和已有的 FutureFC / 后续 mask-token
  自监督信号联合训练，并明确它在这条路线里的定位（正则器，而非主机制），这样实验消融也好写。
